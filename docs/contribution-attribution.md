# Mathematical Contribution Attribution

[Overview](../README.md) · [Infrastructure](infrastructure.md) · [Research gaps](research-gaps.md)

目标是形成可核对的解释：论文的主张是什么，证明由哪些部分支撑，哪些内容已有先例，以及剩余的数学工作是什么。新颖性按内容和关系定性分析，不能由模型自述或检索空白自动决定。

以下是拟采用的分析协议；尚不是经过验证的归因系统或标注标准。联合前提、独立标注维度和诊断案例见[任务规范](task-specification.md)，直接近邻的范围见[重叠审查](overlap-audit.md)。

## 1. Separate the attribution questions

| 维度 | 分析对象 | 可能的结论 | 所需证据 |
| --- | --- | --- | --- |
| 结果新颖性 | 命题本身 | 新结果、范围推广、较弱版本、重述、反例、未决 | 前作的精确陈述与时间；对象、假设、结论的比较 |
| 证明新颖性 | 路线、构造、关键引理与连接 | 沿用、改造、新证明路线、未决 | 当前证明与前作的局部对应，以及实质差异 |
| 问题或场景 | 新对象、新假设组合、新应用场景 | 问题扩展、实质迁移、表述变化、未决 | 原有适用范围，以及迁移中新增的数学义务 |
| 反例贡献 | 被推翻的命题与构造 | 已知反例、新构造、新范围、未决 | 原命题版本、反例有效性及先前构造 |
| 过程贡献 | 人、模型、工具与文献的作用 | 提出、检索、证明、修复、验证、整理 | 提示、编辑、工具调用和人工操作记录 |

结果新颖性与证明新颖性分别判断。使用已知工具可以得到新结果；对已知结果也可能给出有价值的新证明。过程贡献另行记录：文献对应只说明先例和依赖证据，不能单独证明模型在生成时接触过某篇论文。

## 2. Represent the argument

采用主张和推导组成的有向依赖图，而不是强制把全文压成线性十步。已有 Lean Blueprint 与 TheoremGraph 等相关基础，表示方式本身不作为新颖性主张；见[相关工作](related-work.md)。

- **节点**：定义、假设、引理、主张、构造或主定理，带原文位置。
- **推断**：一组前提在给定上下文下共同推出结论；用推断节点或超边保留共同作用，不能误读为每个前提单独推出结论。指出使用的工具、条件与待补义务。
- **外部依赖**：前作中的具体定理、公式、构造或证明片段，固定版本与位置。
- **状态**：论证是否充分、先例对应是否确认、专家是否复核，分别存储。

正文段落用于定位，数学主张用于分析；一个段落可能包含多个推导，一个推导也可能跨越多个段落。

## 3. Locate the non-routine transitions

下面是**示意案例，不对应任何真实论文**。假设一条主证明的主干包含十步：

| 部分 | 发现的证据 | 适当的分析 |
| --- | --- | --- |
| 1–3 | 前作 A 的一个引理在相同假设下给出所需结论 | 标记既有依赖，逐项核对引用和条件 |
| 3 → 4 | 需要把 A 的结论用于新的对象，前作缺少相应条件 | 把“新对象是否满足条件”列为待证明义务 |
| 4–7 | 在第 4 步成立后，标准定理即可推出 | 暂列 routine 候选，记录推导并请专家确认 |
| 7 → 8 | 前作 B 有相关构造，但关键不变量需要改变 | 列为实质改造候选，明确变化及其作用 |
| 8–10 | 已确认结果的组合给出主定理 | 检查组合本身是否有新的障碍，再判断贡献 |

3 → 4 有三种不同的可能：前作 C 已解决它；它是领域内标准迁移；它确实需要新引理。若论证尚未完成，则仍有待补义务。来源对应、routine 判断和论证状态不互斥：已知路线中也可能出现缺口，新改造也可能尚未完成。不能仅因作者省略解释就认定创新，也不能仅因组成工具都已知就否定新连接。

## 4. Check a local correspondence

每条“与前作对应”的判断至少回答：

| 项目 | 要记录的内容 |
| --- | --- |
| 当前内容 | 哪个版本的哪条主张、公式或推导边 |
| 候选前作 | 标识、公开时间、实际读取版本、精确位置 |
| 数学对应 | 统一符号后，对象、假设、结论与构造如何匹配 |
| 适用性 | 是否需要额外条件，前作是否真的覆盖当前结论 |
| 差异 | 结论更强、范围更广、对象变化或关键步骤替换 |
| 主证明中的作用 | 哪些后续结论依赖这一步，是否位于关键路径 |
| 引用情况 | 是否引用，是否针对这项内容，是否通过明确中间引用指向来源 |
| 复核状态 | 自动提出、证据核对、专家确认、争议或未决 |

候选检索与对应验证使用独立阶段；两侧都必须有可查看的位置。相似措辞、共享术语和相同领域只是检索信号。

## 5. Define routine relative to a context

routine 需要给定领域、允许使用的先验结果和证明粒度。可以提出“在 A、B 成立时，使用标准定理 T 即可推出”的可核对解释；不能只给出一个主观标签。

自动 tactic 成功可以说明某个形式化陈述在给定环境中容易完成，不能据此判定人类数学中的常规程度。反过来，长 tactic 脚本也不意味着概念创新。需要区分形式化工程成本与数学洞察。

## 6. Read the closest evidence carefully

### math-lineage: content-level provenance

[math-lineage](https://github.com/jnshi/math-lineage)给出当前文本与前作的位置对应，同时区分数学关系、重要性和引用状态。它针对缺失归因的报告，不能直接当作整篇论文的完整贡献分析。

一个值得查看的[实际报告](https://github.com/jnshi/math-lineage/blob/da8c0e694f00c2575ccf9d26c0ea560543ef0a1b/preprints/Full-support-of-the-zero-temperature-Sherrington-Kirkpatrick-order-parameter-September-27-2026/README.md)展示了为什么“在参考文献中出现”与“具体内容得到恰当归因”要分开。该报告是代理生成的案例，未经本文独立数学核验；这里借鉴其证据组织方式，不采纳其中具体归因结论作为事实标签。

### OSVerify: proposal and validation

[§3](https://arxiv.org/html/2610.18089v1#S3)中的分层检查为局部审阅提供方法参照。对归因可以研究相似的工作分工：提出潜在对应、寻找反证、核对条件，再交由专家确认。但“存在一个致命错误即可否定证明”的判定逻辑不适用于新颖性：一个旧步骤不会否定整篇论文的贡献，一个无先例候选也不能证明整篇论文原创。

### Who Solved It?: aggregate evidence

[SSRN 文章](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=7607840)讨论汇总指标、学科分层及文献依赖对“AI 解决问题”叙述的影响。当前可读范围为公开摘要，PDF 访问返回 403；不评价其统计实现，也不把其具体统计当作已复现结果。

对本研究的启示是需要分开报告文献依赖、结果验证和新颖性；引用数量是宏观信号，不能代替步骤级归因。检索或提供文献的受控消融也不能抹除模型预训练中的既有知识。

## 7. Report the residual contribution

最终输出应说明已确认的既有部分、标准推导、实质改造候选、新连接候选和未决项，并标出它们如何支撑主定理。避免把未匹配步骤的比例称为“AI 原创率”。

最低可复核交付物包括：证明依赖图、逐条对应证据、差异说明、检索覆盖记录及专家判断。过程日志可用于另一个问题——实际由谁完成哪些操作——但不能从缺失日志推断无人参与。
