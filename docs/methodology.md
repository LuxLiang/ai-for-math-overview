# Selection and Evidence

[Overview](../README.md) · [Projects](resources.md)

## Selection criteria

基础项目优先选择具有持续社区使用、标志性研究结果或广泛可复用性的上游实现。收录理由需要说明它代表哪一层基础设施或技术路线，而不是仅凭“与 AI 数学有关”。不按 star 数自动排序，也不将维护者的宣传等同于能力证据。

- 同一项目的历史模型和版本合并，只保留当前分析所需的代表入口。
- 同类轻量包装器、功能重复工具、个人复现与无独立技术作用的代理不单列。
- 官方只公开部分组件时，明确说明范围；发布论文不等于开放完整系统。
- OSVerify 和 math-lineage 因直接关联贡献归因而作为专题案例，和成熟基础设施区别标注。
- 近邻新颖性研究放在论文与研究缺口中，不能因研究相关便当作有广泛影响的成熟项目。

## Evidence levels

| 证据 | 支持的描述 | 需要保留的限制 |
| --- | --- | --- |
| 官方代码与文档 | 输入输出、开放组件、使用接口 | 文档核对不等于实际复现 |
| 作者报告的基准实验 | 在报告设置下的任务表现 | 模型、版本、采样、预算和人工输入 |
| 形式化证明材料 | 指定环境下的陈述验证 | 陈述忠实性、占位证明、公理与环境依赖 |
| 人工核对的局部对应 | 两份文献的具体数学关系 | 专家范围、争议、版本和时间 |
| 代理生成的报告 | 候选线索及其证据格式 | 不直接视为金标准或采纳其指控 |
| 仅摘要 | 作者声称的研究问题和方法概况 | 不评估全文推导、实现或具体统计复现 |

## Interpretation

研究缺口来自本索引覆盖范围内的比较，不能推导出“领域内不存在解决方案”。routine、新颖性、历史先例和实际生成过程需要不同证据；任何未检索到或无法访问的内容保留为未知。

仓库不维护跨预算的混合排行榜，也不把引用比例、形式化覆盖比例或文本相似度解释为数学贡献比例。
